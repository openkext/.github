# Contributing to OpenKext

Thanks for helping. The same rules apply to every repository in this organization.

- **Tests.** Every code change comes with tests and must pass the repository's checks in CI.
- **AI use.** If you used an AI tool, say which tool and model in the pull request. That's fine; hiding it isn't.
- **Licenses.** Only open-source work. Keep upstream license notices, and say where code came from.
- **Apple software.** Never commit Apple binaries, kexts, kernel collections, firmware, disassembly or decompiled code, or headers copied from Apple SDKs or KDKs. Reverse engineering for interoperability happens on your own licensed copy of macOS, and only the minimum needed (class names, slot order, struct offsets) is committed, in your own words.
- **Privacy.** Test reports and logs are public. Leave out serial numbers, MAC addresses, network names and anything else personal.

For the registry (listing projects and test reports), see its [GOVERNANCE.md](https://github.com/openkext/registry/blob/main/GOVERNANCE.md): most pull requests there are checked and merged by a bot.
